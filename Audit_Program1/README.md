# Audit-Plus — البرنامج الرئيسي للمراجعة الخارجية (v4.3.7)

برنامج يعمل بالكامل داخل المتصفح (بدون خادم)، بواجهة عربية/إنجليزية. الكود مكتوب الآن كـ **ES modules** ويُبنى بـ **esbuild**.

## التشغيل السريع

```bash
npm install            # مرة واحدة
npm run dev            # يشغّل http://127.0.0.1:5173/  (يخدم المصدر كوحدات ES أصلية؛ حدّث الصفحة بعد كل تعديل)
npm run build          # ← dist/  (انظر أدناه)
npm run lint           # ESLint (أخطاء فقط؛ يكشف الأسماء غير المعرّفة)
npm run format         # Prettier
npm run check          # تنسيق + lint + بناء
npm test               # اختبار الدخان (Playwright، انظر "الاختبارات")
```

> **مهم:** ملف `index.html` في جذر المشروع هو **قالب التطوير** ويحمّل `js/main.js` كوحدة ES، والمتصفح يمنع وحدات ES عند الفتح المباشر
> من القرص (`file://`). لذلك: للتطوير استخدم `npm run dev`، وللاستخدام العادي افتح ملف `dist/` الناتج عن البناء.

## ناتج البناء (`npm run build`)

| الملف | الوصف |
|---|---|
| `dist/index.html` + `dist/assets/*` | حزمة JS واحدة مصغّرة + CSS مصغّر + الخطوط. **يعمل بالفتح المباشر من القرص.** |
| `dist/Audit-Plus-standalone.html` | كل شيء في ملف واحد (CSS والخطوط والـ JS وقاموس الإنجليزية) — للتضمين في iframe أو الرفع كصفحة مفردة. |
| `npm run build -- --dev` | نفس الناتج بدون تصغير ومع source maps مضمّنة. |

## كيف تعمل الوحدات (ES modules) و«المحور» hub

- كل ملف JS الآن وحدة مستقلة: يستورد ما يحتاجه `import { x } from '…'` ويصدّر ما تحتاجه الوحدات الأخرى `export { … }`.
  أخطاء الأسماء (حرف خاطئ، نسيان import) تظهر فورًا في `npm run lint` بدل أن تنكسر وقت التشغيل.
- **ترتيب التنفيذ** هو ترتيب الاستيراد في `js/main.js` وهو نفسه ترتيب `<script>` القديم. كل `import` في المشروع يشير **للخلف** فقط
  (إلى ملف يسبق الملف الحالي في القائمة)، فلا توجد دورات استيراد.
- بعض الارتباطات لا يمكن أن تكون `import` عادية: (1) دالة في ملف مبكر تستدعي دالة معرّفة في ملف **لاحق**، (2) قيم تُكتب من ملف آخر
  (`SESSION`, `STORE`, `TBMV`…)، (3) دوال تستبدلها وحدة لاحقة عمدًا (`tabsHTML = function…`). هذه (109 اسمًا) تمر عبر `hub`:
  المالك يسجّلها مرة واحدة بـ `defineHub({ name: [() => name, v => { name = v }] })` والبقية تقرأ/تكتب `hub.name`.
  عند إضافة ارتباط جديد يشير للأمام، استخدم `hub.name` بنفس الطريقة (أو الأفضل: أعد ترتيب الملفات ليصبح الاستيراد للخلف).
- **لإضافة ملف جديد**: أنشئه في المجلد المناسب، ثم أضف سطر `import './path/file.js';` في `js/main.js` في الموضع الصحيح.
- ملف `js/modules/19-tb-worker.js` يُحوَّل نصيًا (`toString`) إلى Web Worker، فلا تستخدم فيه أي متغيرات أو imports من خارج الدالة.
  (يُبنى بهدف `esnext` حتى لا يحقن esbuild دوال مساعدة خارجها.)

## مشاكل معروفة (كشفها ESLint، لم تُعدَّل عمدًا حفاظًا على السلوك)

- 85 موضعًا تُعاد فيها كتابة دالة بعد تعريفها (`x = function…`): دَين تقني يظهر كتحذيرات `no-func-assign`.
- أربعة أسماء يُشار إليها خلف `typeof`/`try` ولا تُعرَّف في أي ملف: `TB` (بحث ميزان المراجعة في اختيار الإحالات لا يعمل فعليًا؛ الكائن الفعلي `TBSTORE` وبحثه غير متزامن)،
  `rnForm`، `PB_LEGACYMAP`، `refreshTabCounts` (استدعاؤها يفشل بصمت داخل `try`).
